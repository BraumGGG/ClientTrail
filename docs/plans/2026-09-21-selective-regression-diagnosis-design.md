# ClientTrail 选择性回归与失败诊断设计说明

## 背景与目标

真实双实例测试表明，ClientTrail 已能形成 objective 闭环，但仍有两个轻量可靠性缺口：每次变更缺少明确的测试范围选择规则；外层 runner 超时或适配器失效时，objective 仍可能被项目测试误写为业务 `assertion`。

本次只增加三项能力：

1. 默认执行与变更直接相关的目标和固定共享边界补测；
2. 满足明确的不确定条件时，每个测试请求最多升级一次完整回归；
3. runner 被超时终止、启动失败或适配器失效时，校正缺少业务证据的 objective 分类，并输出首个致命信号摘要。

## 约束

- 不实现自动依赖图、动态评分或动态 timeout。
- 不自动重试失败测试。
- 不把项目专用模块名写入 Core。
- 有明确业务阶段或证据引用的 assertion 不被覆盖。
- 缺少实例 provenance 只形成可见告警，不伪造实例事实。

## 方案

### 选择性回归

Skill 先从测试契约、已有测试入口和变更文件中选择直接目标，再按项目声明的共享边界补测。无法映射、共享边界无声明、选择结果为空、契约不完整或测试基础设施变更时标记为不确定，并将本次请求升级一次完整回归。完整回归失败后停止，不因“不确定”再次重跑。

### Objective 分类校正

Core 在最终化前读取运行级失败分类。若 runner 被强制超时终止，或运行在启动/环境/适配器阶段失败，则只校正没有业务阶段、没有证据引用且被写成 `assertion` 的 objective：最早的一个成为运行根因，后续同类失败变为 `blocked`。明确带有业务阶段或证据引用的断言保持不变。

### 失败信号摘要

Tauri adapter 从 stdout/stderr 提取少量稳定信号：首个致命日志行、脚本执行超时、连接拒绝、channel closed、外层 runner 终止信号。摘要写入 `result.json`，不承担自动恢复。

## 测试策略

- Core 单元测试覆盖超时校正、显式业务断言保留和后续阻塞传播。
- Adapter 单元测试覆盖日志信号摘要。
- Skill 契约测试覆盖直接目标、共享边界、不确定条件、单次升级和禁止自动重试。
- 完整执行 typecheck、单元测试和 Skill 快速校验。
